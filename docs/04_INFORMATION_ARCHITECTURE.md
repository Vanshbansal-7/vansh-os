# Philosophy

Vansh OS is not organized by features.

It is organized by human workflow.

Every screen exists because it supports a real action performed during the day.

Navigation follows the founder's thinking process.

Not software conventions.

# Dashboard Relationships

Dashboard does not own information.

Dashboard displays information.

All data originates from its own pillar.

Dashboard aggregates.

Never duplicates.

# Navigation Rules

Maximum depth:

3 clicks.

Every important action

≤2 clicks.

Back button should always make sense.

No dead ends.

---

# Data Ownership

Each pillar owns its data.

Dashboard never owns data.

Dashboard only displays it.

This prevents duplication.

---

# Final Principle

The user should never think

"Where is this?"

The architecture has failed if searching for features becomes necessary.

Everything should feel exactly where the user expects it.
